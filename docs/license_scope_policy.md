# File scope and new release documentation

The approved initial inventory has 116 rows in `manifests/license_scope.csv`: 37 Python files under MIT and 79 own non-text numerical/identifier/configuration/provenance/documentation files under CC BY 4.0. Python comments and docstrings travel with their mapped MIT file. The license choice is fixed per file; recipients cannot choose MIT for a CC BY file or CC BY for an MIT file merely because both licenses occur in this repository.

Four new administrative files implement that approved scope: `LICENSE`, `manifests/license_scope.csv`, `.zenodo.json`, and this policy. Their original scope wording/compilation is CC BY 4.0 as release documentation; the standard MIT text remains the unmodified license text. They are named explicitly rather than self-hashed in their own content. The export manifest hashes these files and omits only its own hash; an external archive manifest binds the complete ZIP. The license table stores previous reviewed hashes, not a recursively changing current hash of itself.

No extension-based blanket rule licenses arbitrary future additions. Any new file must be named, its actual origin/rights reviewed, and its license/exclusions recorded before export. Original release metadata generated from approved own materials may be CC BY 4.0 when explicitly recorded, while external text, package/model material and private records retain separate rights. New scientific inputs/outputs or a changed rights scope require their own review and must not be hidden as packaging updates.

The columns in the scope CSV are release-relative `path`, assigned SPDX `license`, `previous_candidate_version`, `previous_candidate_sha256`, original `origin`/`origin_sha256`, author-controlled `rights_scope`, recorded `ownership_evidence`, actual `license_applied_utc`, `copyright_holder` and `copyright_year`. Empty origin hashes mean an original new release-layer file, not missing scientific data. Multiple origin hashes are pipe-separated in the same order as their origin paths. This table describes licensing/provenance; it has no mask rate, replicate denominator or inferential family. Full field definitions and missingness are in the data dictionary.

These licenses do not create exclusive rights over factual identifiers/values, license omitted external inputs, change scientific freeze identities, authorize journal submission, or imply institutional endorsement. The individual author controls only the rights they are authorized to grant.
